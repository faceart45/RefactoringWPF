## 🔴 Критические проблемы (ломают работу приложения)

### 1. DataGrid не отображает данные

- **Причина:** в классе `Order` используются **публичные поля** вместо **свойств**.
    
- **Симптом:** таблица пуста, несмотря на добавленные заказы.
    

### 2. Коллекция заказов не уведомляет UI об изменениях

- **Причина:** используется `List<Order>` вместо `ObservableCollection<Order>`.
    
- **Симптом:** после добавления/удаления таблица не обновляется автоматически.
    

### 3. Небезопасный ввод пользователя

- **Причина:** `int.Parse` / `decimal.Parse` без `TryParse` и без обработки исключений.
    
- **Симптом:** при вводе буквы или пустой строки — падение приложения.
    

### 4. NullReferenceException при удалении/скидке

- **Причина:** `dgOrders.SelectedItem as Order` без проверки на `null`.
    
- **Симптом:** нажатие «Удалить» без выделенной строки — краш.

## 🟠 Архитектурные проблемы (нарушение SOLID)

### 5. Класс-бог `OrderService`

- **Причина:** один класс отвечает за CRUD, расчёты, фильтрацию, логирование, скидки.
    
- **Нарушение:** SRP (Single Responsibility Principle).
    

### 6. Жёсткая связанность (нет DI)

- **Причина:** `new OrderService()` создаётся прямо в `MainWindow`.
    
- **Нарушение:** DIP (Dependency Inversion Principle).
    

### 7. Логика в code-behind (нет MVVM)

- **Причина:** вся бизнес-логика в `MainWindow.xaml.cs`.
    
- **Нарушение:** разделение представления и логики.
    

### 8. Условные конструкции вместо стратегий

- **Причина:** `if/else if` для скидок и статусов.
    
- **Нарушение:** OCP (Open/Closed Principle).

## 🟢 Проблемы читаемости и чистоты кода

### 11. Магические строки статусов

- **Где:** `"new"`, `"paid"`, `"shipped"`, `"cancelled"` разбросаны по коду.
    

### 12. Магические числа в скидках

- **Где:** `100`, `50`, `10`, `10000` в `GetDiscount`.
    

### 13. Неинформативные имена

- **Где:** `Button_Click`, `Button_Click_1`, `Button_Click_2`, `Button_Click_3`.
    

### 14. Мёртвый код

- **Где:** `Helper.CalculateSomething`, `Helper.FormatMoneyShort`.
    

### 15. Булев параметр в методе

- **Где:** `UpdateStatus(int id, string newStatus, bool writeLog)`.
    
- **Проблема:** флаг-параметр — признак плохого дизайна.
    

### 16. Наивная валидация email

- **Где:** `Helper.IsValidEmail` — проверяет только `@` и `.`.
    
- **Симптом:** принимает `Customer@dsf.`
    
- **Требование:** использовать `MailAddress` или регулярное выражение.
    

### 17. Хардкод в XAML 

- **Где:** `Text="Customer"`, `Text="Product"` в `TextBox`.
    
- **Проблема:** пользователь видит текст как значение, а не подсказку.
    
- **Требование:** использовать placeholder/watermark через стили.
    

### 18. Автогенерация колонок DataGrid

- **Где:** `AutoGenerateColumns="True"`.
    
- **Проблема:** нет контроля над заголовками, порядком, форматом.
